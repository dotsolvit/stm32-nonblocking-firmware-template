# Шаблон Неблокуючої Прошивки для STM32F103

[Read me in English](README.md) | **Читати мене Українською**

Готовий до використання шаблон подієво-орієнтованого (event-driven) вбудованого ПЗ для мікроконтролера **STM32F103C8T6**, розроблений на базі бібліотеки **STM32CubeHAL**. Проєкт демонструє побудову чистої асинхронної архітектури, низькорівневу роботу з Flash-пам'яттю, реалізацію кільцевих буферів та точну конфігурацію периферії.

## 🎯 Головна мета проєкту
- **Повна відсутність блокуючого коду:** Побудова асинхронної архітектури основного циклу програми без використання затримок типу `HAL_Delay()`.
- **Ефективність обробки переривань:** Оптимізація обробників переривань (ISR) для мінімальної латентності системи та захисту атомарності спільних даних.
- **Комплексна інтеграція периферії:** Об'єднання незалежних апаратних модулів (Flash, UART, Таймери/ШІМ, EXTI, АЦП) в єдину та стабільну систему.

## 🛠️ Технічні характеристики платформи
- **Цільовий МК:** STM32F103C8T6 (ARM Cortex-M3 @ 72 МГц)
- **Тактування системи:** Зовнішній кварцовий резонатор 8 МГц (HSE), частота ядра через PLL налаштована на максимум — **72 МГц**.
- **IDE та компілятор:** STM32CubeIDE (GCC Compiler / Make build system)
- **Конфігуратор заліза:** STM32CubeMX

## 📊 Апаратна верифікація та інженерні розрахунки
Через відсутність фізичного цільового чіпа на етапі розробки, вся асинхронна бізнес-логіка прошивки була повністю перевірена та верифікована "в залізі" за допомогою плати STM32F072 Discovery (48 МГц), цифрового осцилографа **OWON SDS210S** та USB-UART моста в режимі Loopback.

При конфігурації платформи були реалізовані такі точні інженерні розрахунки:
1. **8-бітна роздільність ШІМ (PWM):** Для можливості прямого запису прийнятих по UART сирих байтів (0–255) в регістр порівняння таймера (`TIM1->CCR1`) без витрат на математичне масштабування, період таймера (`ARR`) зафіксовано на позначці **255**. Для частоти шини 72 МГц значення Prescaler (`PSC`) розраховано як:
   Prescaler = ( 72,000,000 Hz ) / ( ( 5,000  Hz) * 256) - 1 = 55.25 ≈ 55
   *Це забезпечує реальну фізичну частоту ШІМ 5.02 кГц, що повністю вкладається в інженерну похибку допусків.*
2. **Управління топологією сторінок Flash:** У мікроконтролерах STM32F103 розмір сторінки Flash становить **1 КБ**. Адреси з ТЗ (`0x0800FC00` - `0x0800FC03`) припадають точно на початок останньої сторінки пам'яті (**Page 63**). Функція стирання `HAL_FLASHEx_Erase` очищує рівно 1024 байти на самому краю матриці кремнію, що є повністю безпечним і гарантує збереження коду самої програми.
3. **Обмеження тактування АЦП:** Щоб забезпечити паспортну частоту тактування АЦП не вище 12 МГц при системній частоті 72 МГц, апаратний дільник шини APB2 для АЦП (`ADC Prescaler`) у дереві тактування CubeMX був примусово виставлений у значення **`/6`** (72 МГц / 6 = 12 МГц). Опорна напруга 3.3 В виступає базовою шкалою вимірювання (4095 одиниць = 3.3 В).

## 💻 Архітектура вбудованого ПЗ та рішення розробки
- **Неблокуючий таймер подій:** Періодична відправка пакетів у UART2 реалізована через порівняння мікросекундних міток `HAL_GetTick()`. Це виключає затримки та забезпечує миттєву реакцію процесора на зміну логічного стану на дискретному вході `PB2`.
- **Асинхронна взаємодія переривань:**
  - **`EXTI0` (Вхід на PA0):** Спрацьовує по спаду сигналу, миттєво запускає разове аналогово-цифрове перетворення через `HAL_ADC_Start_IT` і відразу завершує роботу, мінімізуючи час перебування в ISR.
  - **`ADC1` (Завершення заміру):** Функція зворотного виклику `HAL_ADC_ConvCpltCallback` зчитує 12-бітне значення у `volatile` змінну та піднімає статусний прапорець без блокування ядра.
  - **`USART2` (Прийом байта):** Реалізує оптимізований **циклічний кільцевий буфер (Ring Buffer) на 20 байт** за допомогою арифметики залишку від ділення (`(rx_index + 1) % BUFFER_SIZE`), оновлює ШІМ через офіційний макрос `__HAL_TIM_SET_COMPARE` та миттєво перезапускає переривання прийому.
- **Обробка апаратних помилок:** У коді прописано функцію `HAL_UART_ErrorCallback`. Якщо на лінії виникає завада, шум (NE) або переповнення буфера (ORE), переривання фіксує помилку, очищує прапорці та примусово перезапускає IT-приймач, захищаючи систему від мертвого зависання (deadlock). Робота з Flash контролюється через перевірку статусів `HAL_StatusTypeDef` та функцію `HAL_FLASH_GetError()`.
